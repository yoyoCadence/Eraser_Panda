# Eraser Panda — 需求規格 (Requirements)

> 狀態欄：✅ 已完成　🚧 進行中　⬜ 未開始。進度以 `docs/PLAN.md` 為準。

## 0. 目標與前提

**目的**：使用者 **已確認** 某份文件的內容可以上傳到外部 / AI 服務，但文件中的「分級標籤字眼」（Confidential、Sensitive、Secret、機密…）、公司 Logo、敏感度標籤 metadata 會讓 DLP / 上傳閘道誤報。本工具在本機快速找出並移除這些識別資訊，輸出一份新檔案，原檔不動。

**不是**：
- 不是用來判斷「文件能不能外流」的工具 —— 那個判斷是使用者的責任，本工具假設已經做完。
- 不是 PII 去識別工具（人名、身分證、電話）—— v1 不做，但自訂 regex 規則可以涵蓋部分情境。

## 2. 未明說、但要達成目的必須具備的需求 (I)

### 2.1 涵蓋範圍 —— 只刪「看得到的字」不會讓 DLP 閉嘴

| ID | 需求 | 為什麼 |
|----|------|--------|
| I1 | **所有格式都掃 metadata**，不只 Excel：Office `core.xml` / `app.xml` / `custom.xml`、**`MSIP_Label_*`（Microsoft Purview 敏感度標籤）**、`docMetadata/LabelInfo.xml`、`customXml/*`；PDF Info 字典、XMP metadata | DLP 最常觸發的其實是敏感度標籤 metadata，不是可見文字。只刪內文等於白做 |
| I2 | **隱藏位置的文字**：頁首/頁尾、浮水印（Word VML/WordArt、PDF Watermark Artifact、Acrobat 圖章註解）、文字方塊、註解/批註、備忘稿、投影片母片/版面配置、圖表標題、Excel 頁首頁尾代碼、Excel 公式內字串、PDF 書籤/註解/表單欄位 | 分級字眼最常出現在這些地方，而不是內文 |
| I3 | **跨片段比對**：Word 常把「Confi」「dential」拆在不同 run；PDF 常把一個字拆成多個繪字指令 | 否則大量漏抓 |
| I4 | **正規化比對**：不分大小寫、全形/半形、多餘空白；英文預設「整字比對」避免 `Secretary` 誤中 `Secret` | 減少誤刪 |
| I5 | 中/英/日 **預設關鍵字庫** + 使用者自訂（公司名、專案代號、regex）；設定存在瀏覽器；可 **匯出/匯入設定檔** 分享給團隊 | 每家公司的標籤字眼不同 |
| I6 | Logo 偵測三策略：(a) 跨頁重複出現在同位置的圖片 (b) 位於頁首頁尾/母片的圖片 (c) **上傳 Logo 樣本，以感知雜湊比對**（最準） | 「抓 Logo」本質是模糊需求，純啟發式一定誤判 |

### 2.2 刪除正確性 —— 刪不乾淨比不刪更危險（給人錯誤的安全感）

| ID | 需求 |
|----|------|
| I7 | **真刪除，不是遮蓋**：PDF 用黑框/白框蓋住，文字仍可被抽取 → 必須從內容串流中移除字形 |
| I8 | **無殘留**：PDF 孤兒物件、增量更新的舊版本、Office 未被引用的 media/rels 都要清掉；移除 part 時同步更新 `[Content_Types].xml` 與 `.rels` |
| I9 | 輸出檔必須能被 Office / Acrobat 正常開啟（不能跳「無法讀取的內容」）；未修改的 part 原封不動保留原始 bytes |
| I10 | 版面盡量不變：PDF 刪字後以字寬補位，同一行後面的字不位移 |
| I11 | Word `DOCPROPERTY` 欄位若引用被刪除的屬性，要一併處理，避免開檔後顯示「錯誤! 未知的文件屬性名稱」 |

### 2.3 信任 —— 使用者要能「證明」處理成功

| ID | 需求 |
|----|------|
| I12 | **輸出後自動驗證**：重新掃描輸出檔（包含解壓後的原始串流 bytes），顯示「殘留 0」；有殘留就警示 |
| I13 | **100% 本機處理**：檔案絕不離開電腦；HTML 內嵌所有程式碼，以 CSP 禁止任何網路連線；可離線、可用 `file://` 直接開 |
| I14 | **處理報告**：每個檔案移除了什麼（類型/位置/原文），可匯出 JSON/CSV 作為稽核紀錄 |

### 2.4 使用體驗

| ID | 需求 |
|----|------|
| I15 | 批次多檔；逐檔下載或打包 ZIP；輸出檔名 `原檔名_clean.副檔名` |
| I16 | 每個發現標示 **位置類型**（頁首/頁尾/浮水印/內文/Metadata/Logo）；**內文中的出現**（刪了可能改變語意，例如合約裡的 "Confidential Information"）要醒目標示，並可一鍵「只取消內文項目」 |
| I17 | 處理前 / 處理後對照預覽 |
| I18 | 進度顯示；大檔不凍結畫面 |
| I19 | 錯誤要講人話：密碼加密檔、**MIP/RMS 加密檔**（無法處理，需先在 Office 內降級標籤）、舊格式 `.doc/.xls/.ppt`（請先另存新格式）、損毀檔 |
| I20 | 介面繁體中文為主，可切英文 |

## 3. 風險與盲點（請正視）

1. **這是「標籤移除器」——從資安團隊的角度，它和外洩工具長得一模一樣。** 前提「已確認可外流」只存在你的腦中，工具無法驗證。建議：取得資安/法遵書面同意、保留 I14 的稽核報告。
2. **移除標籤 ≠ 不會被攔。** DLP 可能還有內容指紋（EDM / document fingerprinting / 關鍵字字典），本工具只處理「標籤型」誤報。
3. **Purview 強制標籤環境**：移除 `MSIP_Label_*` 後，Office 開檔可能要求重新標籤；降級動作本身可能已被稽核記錄。**已加密 (RMS) 的檔案本工具不能、也不應處理。**
4. **Logo 偵測是啟發式**，必有誤判 → 預設要人工確認，或使用樣本比對。
5. **刪內文會改變語意**（例如 "Confidential Information means…"）→ I16。

## 4. 驗收標準（v1）

- 拖入一個含「頁首 Confidential + 浮水印 + MSIP 標籤 + 頁首 Logo」的 docx / xlsx / pptx / pdf，30 秒內列出全部發現並可預覽位置。
- 一鍵刪除後輸出 `*_clean.*`，原檔不變；輸出檔可被 Office / Acrobat 無錯誤開啟。
- 輸出檔的驗證掃描顯示殘留 0（被標記為例外者除外）。
- 全程無任何網路請求（以 CSP + E2E 測試驗證）。
